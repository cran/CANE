Pooled analysis of multi-environment trials with CANE

library(CANE)

The problem

A single experiment at one site in one season answers a narrow question. Crop improvement and agronomy therefore repeat the same experiment across locations, seasons or years, and the quantity of interest becomes the treatment-by-environment interaction: do treatments rank consistently, or does the best treatment depend on where and when it is grown?

Pooling such a series is not simply a matter of fitting one larger model. The classical workflow has four prerequisites, and each is easy to get wrong:

  1. each environment must first be analysed on its own, with every effect tested against the error term that the design assigns to it;
  2. the error variances of the environments must be compared, because heterogeneous errors invalidate the pooled F-tests;
  3. if they are heterogeneous, the data must be rescaled before pooling; and
  4. the pooled treatment means must be separated using the correct error stratum, and interpreted in the light of the interaction.

CANE performs all four in one design-specific function call.

The five functions

data.frame(
  Design = c("Completely randomised", "Randomised block", "Latin square",
             "Split plot", "Strip plot"),
  Function = c("PooledCRD()", "PooledRBD()", "PooledLSD()", "PooledSPD()",
               "PooledStPD()"),
  `Error strata` = c(1, 1, 1, 2, 3),
  `Design arguments` = c("-", "Replication", "Row, Column",
                         "Replication, MainPlot, SubPlot",
                         "Replication, RowFactor, ColumnFactor"),
  check.names = FALSE)
#>                  Design     Function Error strata                     Design arguments
#> 1 Completely randomised  PooledCRD()            1                                    -
#> 2      Randomised block  PooledRBD()            1                          Replication

All five share the same interface: data, Response, Location, the design-specific factors, alpha, Mult_Comp_Test, and optionally transform and env_effect. There is no omnibus function that handles every design; the user chooses the function matching the design that was actually conducted.

The largest error mean square is more than a hundred times the smallest, so the error variances are clearly heterogeneous. Bartlett’s test is sensitive to non-normality, which is why CANE reports the median-centred Brown-Forsythe form of Levene’s test beside it, and the environment-wise Shapiro-Wilk tests as well:

#> 2     SGA-IIP 36 0.9618970 0.245817020

Both tests agree here, so the decision to rescale is secure. When they disagree, prefer Levene, and use transform = "always" or transform = "never" to take the decision yourself rather than leaving it to a threshold.

Step 3: the transformation

fit$Transformation$applied
#> [1] TRUE
cat(fit$Transformation$reason)
#> transform = "auto": Bartlett's test gave P = 4.77e-16 against alpha = 0.05, so the error variances were judged heterogeneous and Aitken's transformation was applied. Levene's test (robust to non-normality) gave P = 3.033e-09.

Aitken’s transformation divides each observation by the square root of the error mean square of its own environment. That yields a useful self-check: after the transformation each environment contributes an error sum of squares equal to its own error degrees of freedom, so the pooled error mean square must come out at exactly 1.

cat(fit$Transformation$diagnostic$note)
#> On the Aitken scale the pooled error mean square of a single-error design equals 1 by construction, because each environment's error sum of squares is divided by its own error mean square. Observed: 1.

#> 'Error' names the mean square used as the denominator of each F-test.

The Error column names the mean square used as the denominator of each F-test. In a randomised block series the environment main effect is tested against the replication-within-environment mean square, because replications are the units within which environments are compared; the treatment effect and the interaction are tested against the pooled error.

Note the caveat attached to the environment main effect on a transformed scale: each environment has been divided by its own error standard deviation, so that term is no longer expressed in t/ha and is not interpretable as a yield difference. Interpretation belongs to the treatment and interaction terms.

Because the analysis was carried out on the transformed scale, the means in the Mean column and the grouping letters both refer to that scale. The arithmetic means on the original scale are given alongside, for reporting in t/ha. They are not an inverse transformation: no single multiplier inverts Aitken’s rescaling, because each environment was divided by a different constant.

Choosing a multiple comparison procedure

Mult_Comp_Test = 1 gives Tukey’s HSD, which controls the family-wise error rate over all pairwise comparisons and is the sensible default when all pairwise differences are of interest. 2 gives Duncan’s multiple range test, whose graduated protection levels buy power at the cost of weaker error control. 3 gives Fisher’s LSD, which makes no adjustment at all; with means it conducts independent tests at level , so the chance of at least one false declaration grows quickly. CANE warns when LSD is requested for more than three treatments. Reserve it for a small number of comparisons planned before the data were seen.

Fixed or random environments

By default environments are treated as fixed, which is appropriate when they are a specific set of target sites or seasons. If the environments are better regarded as a sample from a wider population to which the conclusion should generalise, the treatment main effect should be tested against the treatment-by-environment interaction:

fr <- PooledRBD(sugarcane, "ccsy", "env", "gen", "rep", 0.05, 1,
                env_effect = "random")
r <- fr$Pooled_ANOVA
r[r$Source %in% c("Treatment", "Treatment x Env"), ]
#>  Source          Df Sum Sq Mean Sq F value Pr(>F) Sig Error          
#>  Treatment       17 503.72 29.63   2.042   0.0171 *   Treatment x Env
#>  Treatment x Env 85 1233.5 14.51   14.51   <1e-16 *** Pooled error   
#> ---
#> Signif. codes:  0 '***' 0.001 '**' 0.01 '*' 0.05 '.' 0.1 ' ' 1
#> 'Error' names the mean square used as the denominator of each F-test.

The pooled comparison of means then uses the same mean square, so the grouping letters and the F-test rest on the same denominator:

fr$Treatments_Comparison$parameters[, c("test", "error_stratum", "scale")]
#>          test   error_stratum              scale
#> 1 Tukey's HSD Treatment x Env Aitken-transformed

What CANE is not for

CANE implements the fixed-effects pooled analysis of a balanced series of experiments. It is deliberately narrow. For

  • unbalanced series, or treatment sets that only partly overlap between environments, use a mixed-model package such as nlme or lme4, which handle missing cells properly;
  • augmented designs, in which a few checks are replicated and the test entries are not, use augmentedRCBD (archived on CRAN in April 2026 for an administrative reason; it remains installable from its own repository);
  • the single-trial stage of a mixed-model pipeline, use statgenSTA;
  • explicit modelling of heterogeneous variances or of a spatial covariance structure, use nlme, lme4, sommer or asreml;
  • multiplicative decomposition of the interaction and stability analysis (AMMI, GGE biplots, Shukla’s variance, Eberhart-Russell regression), use metan or ammistability;
  • best linear unbiased prediction of genotype effects for selection, use a mixed-model package.

The pooled ANOVA is the first step of a multi-environment analysis, not the last one. Its value is that it tests the main effects and the interaction exactly and transparently, which tells you whether the more elaborate analyses are worth running.
